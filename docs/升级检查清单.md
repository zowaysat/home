# 升级检查清单

> 适用项目：無名の主页（`imsyy/home` fork）
> 关联文档：[长期维护与二开方案](./长期维护方案.md)
> 用途：每次依赖升级（尤其是大版本）时按本清单执行，确保"可验证、可回滚"。

---

## 1. 使用方式

- **小版本**（patch/minor）：每月一次，可批量合并，走 §3 的简化流程；
- **大版本**（major）：每季度一次，**单独 PR、单独发布**，完整执行 §4–§7；
- 所有升级在**测试基建就绪后**进行（见 §4 Step 1）。没有测试就升大版本 = 赌博。

---

## 2. 升级前检查清单

- [ ] 工作区干净：`git status` 无未提交改动
- [ ] 当前版本已打 tag：`git tag vX.Y.Z && git push --tags`
- [ ] 基线构建通过：`pnpm install --frozen-lockfile && pnpm build`
- [ ] 基线测试通过：`pnpm test -- --run`（若已有测试）
- [ ] 记录基线指标：JS/CSS gzip 体积、构建耗时、Lighthouse 分数
- [ ] 已复制 `.env`（P0 的 env 校验落地前，缺 `.env` 会直接构建失败）
- [ ] 已阅读目标版本的 CHANGELOG / 迁移指南（见 §6）
- [ ] 明确本次升级范围（只升一个包？一组相关包？）
- [ ] 准备好回滚方案（§7）

---

## 3. 小版本批量升级流程（每月）

```bash
git switch -c chore/deps-YYYY-MM
pnpm outdated                 # 查看可升版本
pnpm up --latest              # 或按分组逐组升级
pnpm install
pnpm lint && pnpm test -- --run && pnpm build
```

- [ ] `pnpm-lock.yaml` 变更已提交
- [ ] 本地 `pnpm dev` 手测：加载动画、壁纸、一言、天气、盒子、设置持久化、音乐（若开启）
- [ ] 无新增控制台报错
- [ ] 合并后部署预览环境验证
- [ ] 更新 `CHANGELOG.md`

## 6. 已知破坏性变更速查

| 升级项 | 需要关注 |
|---|---|
| Vite 5 | 移除 CJS Node API；`build.rollupOptions` 行为微调；插件需同步升级 |
| Vite 6+ | 插件兼容矩阵；环境相关配置变化，逐版本看迁移指南 |
| Vue 3.5 | 基本兼容；注意 `reactive` props 解构等新特性不要误用 |
| Element Plus 2.8+ | 主题变量、部分组件 API 弃用（`el-radio` 的 `label` → `value` 等） |
| Pinia 3 | 随 Vue 3.5 评估；`pinia-plugin-persistedstate` v4 的 `paths` 改为 `pick`，需同步改 `src/store/index.js` |
| ESLint 9 | 默认 flat config；`.eslintignore` 失效；插件需支持 flat |
| unplugin-* | `.d.ts` 生成格式变化；resolver 配置变化 |
| vite-plugin-pwa | Workbox 版本、`manifest` 配置结构、`registerType` 行为 |
| sass 2.0 | legacy JS API 将移除；当前已是 modern API，保持即可 |

## 7. 回滚

```bash
# 代码回滚
git revert <merge-commit>        # 或 reset 到 pre-upgrade tag
git checkout pre-upgrade-vX.Y.Z -- pnpm-lock.yaml package.json
pnpm install --frozen-lockfile
pnpm build

# 部署回滚：发布平台上回滚到上一个成功部署版本
```

## 9. 例行维护（固定节奏）

**每月（30 分钟）**

- [ ] 合并小版本依赖 PR
- [ ] 运行 `pnpm outdated` / `pnpm audit`：处理 critical / high 与安全补丁（传递依赖用 `overrides` 固定 patch 版本）
- [ ] 第三方服务探活：hitokoto / 高德 / 音乐 API / 壁纸源 / 字体 CSS
- [ ] 检查线上控制台错误（可选 Sentry）
- [ ] 更新 `CHANGELOG.md`

**每季度（半天）**

- [ ] 评估一个大版本升级（按 §4 执行）
- [ ] 跑一次全量回归（§5）
- [ ] 复核功能开关：失效服务关闭、备用源可用
- [ ] 审查字体/图片体积，必要时压缩

**每半年**

- [ ] 复核 Node LTS / pnpm 版本
- [ ] 复核部署平台与 CI 依赖的 action 版本
- [ ] 评估是否兑现 §7 的三个决策（SEO / TS / 音乐去留）
